## Notes / deviations from the pasted spec

- Added `env_file: .env` to the `app` and `dashboard` services in `docker-compose.yml` (on
  top of the explicit `environment:` overrides for `IB_HOST`/`IB_PORT`/`DATABASE_URL`, which
  must differ from `.env`'s defaults for in-network Docker DNS). Without this, most settings
  in `config.py` (kill switch, poll interval, Telegram, IB mode/client id) wouldn't reach the
  container at all — pydantic-settings' `env_file=".env"` only helps for local (non-Docker)
  runs since `.env` isn't copied into the image.
- Also added `DATABASE_URL` to the `dashboard` service's `environment:` — the pasted compose
  only set it for `app`, but the dashboard reads from Postgres too and needs the in-network
  `db` hostname, not `config.py`'s localhost default.
- `docker/app.Dockerfile` copies `alembic.ini` + `migrations/` in addition to `src/` and
  `dashboard/` — needed so `docker compose run app alembic upgrade head` works from inside
  the container, which is how you'll want to run migrations in practice.
- `uv sync` in the Dockerfile uses `--no-editable`. The default editable install didn't work
  in *this local dev environment* (a Miniconda-based Python where the generated `.pth` file
  wasn't being picked up by `site.py` — unrelated to the project itself, likely specific to
  that interpreter). `--no-editable` sidesteps it and is arguably the right call for a Docker
  image anyway (immutable install, no reliance on `.pth` mechanics at runtime). Local
  `pytest` runs use `pythonpath = ["src"]` in `pyproject.toml` instead, which is robust
  either way.
- `data_dir` in `config.py` defaults to `/data` (the container mount point), not `./data` —
  override `DATA_DIR` in `.env` if running the data-store code outside Docker.
- IBKR contracts are hardcoded to `Stock(symbol, "SMART", "USD")` in both `broker/ibkr.py`
  and `data/sources/ibkr.py`. Fine for US equities/ETFs; will need generalizing (exchange,
  currency, security type) if the strategy ever trades anything else.
- Fixed a latent bug in `data/sources/yfinance.py` while building the backtest harness:
  recent `yfinance` versions return `(field, ticker)` MultiIndex columns even for a
  single-symbol download, so `df["close"]` was silently returning a one-column DataFrame
  instead of a Series (harmless until something actually zipped/iterated it — the existing
  code just sliced `df[[...]]` and returned it, never truly exercising the columns). Now
  flattens to the field level before renaming. Nothing had a test covering this path before.
- This directory is **not a git repository** yet. Nothing has been committed; say the word if
  you want `git init` + an initial commit.

## 2026-09-18 open-order guard

- New `Broker.open_order_symbols()`. IBKR: `reqAllOpenOrders()` filtered by `Trade.isActive()`
  (PendingSubmit, ApiPending, PreSubmitted, Submitted), so orders from other clients and market
  orders queued while an exchange is closed both count. Sim: always empty (instant fills).
- `runner._drop_orders_already_working` runs between sizing and the risk gate. Without it a
  slow or queued order was re-sized from the same stale positions every 5 minutes and stacked.
  If the broker can't answer, the exception aborts the cycle (nothing is placed).
- Tested: working symbols skipped, no stacking over repeated cycles, fail-closed, and the IBKR
  active/inactive status classification using real `ib_async` `Trade` objects.
- Still open: `MAX_NOTIONAL` vs the initial build (7 of 10 orders rejected at 10k CAD), late
  fills never reaching the DB, market (not limit) orders on thin ETFs.

## 2026-09-18 overnight strategy ported (`ibkr_overnight.py` -> engine, original archived)

`ibkr_overnight.py` was a standalone SPY overnight research script (buy the close, sell the next
open; rolling Gaussian-MLE signal, quarter-Kelly sizing, backtest, next-session plan,
untransmitted MOC/OPG order plan, IBKR download, spread screen for cheaper SPY substitutes).
It is now `tradebot/overnight.py` (+ `research/overnight.py` CLI). Original moved to
`../archive/ibkr_overnight.py`.

- **Same rule as the original: it never submits orders.** `order_plan` returns `Order`s with
  `transmit=False`; `to_ib_order` refuses them; `IBKRBroker.place` validates the whole batch
  before sending anything. The runner does not use the overnight strategy, and production use
  still needs the items the module docstring lists (calendar, MOC cutoffs, reconciliation, ...).
- **Fidelity proven before archiving**: original vs port compared with exact equality across 648
  backtest/summary/signal configurations, estimator edge cases, config validation and the spread
  screen (identical). The original's numbers are frozen as golden values in
  `tests/test_overnight.py`, so the check survives the archive. Its own selftest assertions are
  ported as tests too.
- Old `ibapi` client replaced by the engine's `ib_async`: `data/sources/ibkr.download_daily_bars`
  (read-only, ends at midnight UTC so no partial session; TRADES bars = price-only, no dividends).
  `--source yahoo` uses the split- AND dividend-adjusted Yahoo bars for total-return research.
- Real-data smoke tests: Yahoo backtest/signal/plan, and an IBKR download of 501 SPY bars from
  the paper gateway (2024-09-18 -> 2026-09-17), then a backtest from that CSV.
- Result on ~4 years of adjusted SPY (969 sessions, 2 bps roundtrip): strategy +5.5%/yr (vol 6.2%,
  max DD -6.1%), always-overnight +7.0%/yr (vol 9.6%, DD -16.9%), buy & hold +21.7%/yr (vol 15.4%,
  DD -18.8%). Research output, not advice: it trails buy-and-hold on return.

Errors found while checking, and fixed:
1. **`IBKRBroker.place` ignored `Order.order_type`/`limit_price`** and sent everything as a market
   order (a limit order would have become a market order). New `to_ib_order` handles MKT / MOC /
   LMT (+ tif, account, ref) and raises on unknown types, bad quantities or a missing limit price.
2. **Partial batches**: orders were translated and sent one at a time, so an invalid order late in
   a list failed after earlier ones had gone out. The batch is now translated first.
3. **`lookback_days` meant different things per source**: Yahoo `period="Nd"` returns N *sessions*
   while IBKR `"N D"` is calendar days. Yahoo now uses calendar days (365 -> 252 sessions).
   Old vs new fetch agree on every shared date; only the amount of history differs. The earlier
   "365-day" 60/40 backtest (+18.1%, to 2026-08-11) actually covered 365 sessions (~17 months).
   The blended-portfolio windows are unaffected (they are clipped to the youngest ETF).
4. The original script itself: no logic errors found on review (timing lag, MLE, bootstrap and
   cost handling all check out). Only environment drift: it defaulted to TWS port 7497 and the old
   `ibapi`; the engine defaults to the gateway port from settings and connects read-only.
Blended-backtest numbers moved slightly (60/40 12.2% -> 14.0%) only because the window now
includes 2026-09-17, a strong day (SPY +1.1%, TLT +1.1%, USD/CAD +0.5%).
